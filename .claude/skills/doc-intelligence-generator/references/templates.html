CONCEPT TOPIC TEMPLATE

Purpose: Explains what something is, why it matters, and when to use it. Non-procedural, informational content.

Title

Concise, noun-based title that identifies the concept (e.g., "Advanced Search with AI-Powered Filters")

Introduction / Overview

1-2 paragraphs (3-4 sentences each) introducing the concept.
- What is this? (definition)
- Why does it matter? (value/benefit)
- Who uses it? (audience)
Write in present tense, active voice.

Purpose

Explain the primary purpose and business value.
- What problem does it solve?
- What outcomes does it enable?
- Why is this important to users?

Key Concepts

Define 3-5 critical concepts, terms, or principles related to this topic.
Use subsections or definition lists for clarity.
Example structure:

  • Semantic Search: Understanding meaning beyond keywords...
  • Faceted Navigation: Organizing results by categories...
  • Relevance Ranking: Ordering results by relevance to user intent...
When to Use

Scenarios where this concept applies.
- When should users use this feature?
- What problems does it address?
- What are typical use cases?

Related Topics

Cross-references to related concepts, tasks, or references.
Format: See also: [Link to Related Topic](url)

TASK TOPIC TEMPLATE

Purpose: Step-by-step procedures. How to perform a specific action or complete a process.

Title

Start with gerund (verb-ing): "Setting Up...", "Configuring...", "Installing..." or imperative "Set Up...", "Configure..."

Overview / Purpose

1 paragraph explaining what the user will accomplish.
- What task will be completed?
- Expected outcome?
- Time estimate? (if relevant)

Prerequisites

What must be true before starting.
Format as bulleted list:

  • System requirements (OS, permissions, roles)
  • Required access or credentials
  • Prior knowledge or completed tasks
  • Required software or tools
Steps

Numbered, action-oriented steps. Use imperative ("Click", "Enter", "Select").
Each step should be atomic (one action).
Include substeps if needed (1a, 1b, 1c).
Example:

  1. Log in to the admin console with your credentials.
  2. Navigate to Settings → Advanced Search.
  3. Click "Enable Semantic Search".
  4. Select your ML model from the dropdown:
    • Choose "multilingual-e5-large" for multilingual support
    • Choose "all-mpnet-base-v2" for English-only searches
  5. Click Save to apply changes.
Post-Task Information

What happens next, how to verify success, next steps.
- Verification: "You should see a green success message"
- Common next steps
- Troubleshooting tips if applicable

Related Topics

Cross-references to related concepts or advanced configurations.

REFERENCE TOPIC TEMPLATE

Purpose: Structured reference data—API parameters, configuration options, properties. Lookup and fact-based.

Title

Descriptive: "[Feature] API Reference", "[Component] Configuration Options", "[Feature] Properties"

Overview

Brief introduction to what this reference documents.
- What does this reference cover?
- What are common use cases for this reference?

Properties / Parameters Table

Structured table with consistent columns:

Property/Parameter Type Required Default Description Constraints / Examples
query string Yes — Search query in natural language or keywords Max 500 characters. Example: "security updates from last month"
timeout_ms integer No 5000 Request timeout in milliseconds Min: 1000, Max: 30000
cache_results boolean No true Enable result caching for performance Values: true or false
Detailed Property Descriptions (if complex)

For complex properties, provide additional detail beyond the table:

filters (object)

Optional filter object to refine search results.

  • document_type (array): Filter by document type. Values: "guide", "api_reference", "tutorial", "faq"
  • date_range (object): Filter by date range. Contains: from (ISO 8601 date), to (ISO 8601 date)
  • author (string): Filter by document author name or ID
  • tags (array): Filter by one or more document tags
Examples / Sample Usage

Provide examples in code blocks with language markers:

STYLE GUIDELINES FOR ALL TEMPLATES

Writing Style

  • Active Voice: "The system validates queries" not "Queries are validated by the system"
  • Second Person for Tasks: "Click the button" not "The user should click"
  • No Contractions: "cannot" not "can't", "it is" not "it's"
  • Consistent Terminology: Use the same term throughout (API, not "Application Programming Interface" and "API" mixed)
  • Sentence Length: Aim for under 25 words per sentence
  • Paragraph Length: 3-5 sentences per paragraph

Formatting

  • Headings: Use H1 for title, H2 for major sections, H3 for subsections. No skipping levels.
  • Lists: Use bullets for unordered, numbers for sequential. Consistent punctuation.
  • Code: Inline code in backticks, code blocks with language markers (```json, ```python, etc.)
  • Tables: Use for structured data. Header row should be bold with clear column titles.
  • Links: Descriptive link text. "See API Reference" not "click here"
  • Emphasis: Bold for UI elements and defined terms. Italics for emphasis sparingly.

Standards Applied

  • DITA: Topic-based structure, clear titles, proper heading hierarchy, section conventions
  • Microsoft Writing Style Guide: Active voice, clear language, no unnecessary words, second person for instructions
  • IBM Standards: Task structure with prerequisites, consistent formatting, user-centric language
  • Technical Writing Best Practices: Clarity over cleverness, examples, user-focused, accessible language
