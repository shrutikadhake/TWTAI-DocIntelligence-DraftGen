Setting Up Advanced Search with AI-Powered Filters

Overview

This guide walks you through enabling and configuring the Advanced Search feature with AI-powered semantic understanding and intelligent filtering. After completing these steps, your users will have access to natural language search with automatic filter suggestions, faceted result browsing, and personalized ranking. The setup process takes approximately 30 minutes and requires administrator access to your system.

Prerequisites

Before you begin, ensure you have the following in place:

  • Administrator access to your platform with settings and configuration permissions
  • Basic understanding of search concepts, semantic search, and machine learning models
  • Access to the system Administrator Dashboard and configuration panels
  • System requirements: Python 3.8 or higher available on your server infrastructure
  • Disk space: Approximately 2 GB available for ML model files
  • Network connectivity: Access to model repositories for downloading pre-trained language models
  • Optional but recommended: Basic knowledge of your organization's document structure and metadata standards

Step-by-Step Instructions

  1. Log in to the Administrator Dashboard. Open your browser and navigate to the admin console. Enter your administrator credentials. Verify you are logged in successfully.
  2. Navigate to Advanced Search Settings. From the main dashboard menu, select Settings → Advanced Features → Search Configuration. The Search Configuration panel loads.
  3. Enable the Semantic Search Engine. In the Search Configuration panel, locate the toggle labeled "Semantic Search Engine". Click to enable it (toggle should turn blue). You will see a confirmation message: "Semantic search engine initialization started".
  4. Select a Machine Learning Model. A dropdown menu appears after enabling semantic search. Choose your model based on your deployment:
    1. multilingual-e5-large — Recommended for organizations serving multiple languages. Supports over 100 languages with excellent performance.
    2. all-mpnet-base-v2 — Recommended for English-only deployments. Smaller memory footprint, faster inference.
    3. bge-large-en-v1.5 — Recommended for maximum search accuracy. Larger model, requires more system resources (4+ GB RAM).
    For most deployments, select multilingual-e5-large.
  5. Configure Query Timeout. Enter a timeout value in milliseconds:
    • Standard deployments: 5000 (5 seconds)
    • Large datasets (>1M documents): 10000 (10 seconds)
    • Very large deployments (>10M documents): 15000 (15 seconds)
    Enter your value and press Tab to confirm.
  6. Enable Filter Suggestions. Check the box labeled "Enable Smart Filter Suggestions". This allows the system to automatically suggest relevant filters (document type, date, author, tags) based on each search query.
  7. Set Minimum Relevance Score. Use the slider to set minimum relevance threshold (0.0 to 1.0):
    • Conservative (more filtering): 0.7 or higher
    • Balanced (recommended): 0.5
    • Permissive (more results): 0.3 or lower
    The recommended value of 0.5 balances relevance and result coverage.
  8. Enable Personalization. Check the box "Enable Personalized Ranking" to allow the system to adapt search results based on individual user behavior over time. This improves result quality after the system gathers sufficient usage data (typically 2-4 weeks).
  9. Configure Caching (Optional). If performance is a concern:
    1. Check "Cache Popular Search Results"
    2. Set cache time-to-live (TTL) to 3600 (1 hour) for typical deployments
    Caching improves response time for frequently-run searches.
  10. Review All Settings. Scroll through the configuration panel and verify all settings are correct. Check that:
    • Semantic Search Engine is enabled
    • ML model is selected
    • Timeout is set appropriately
    • Filter suggestions are enabled
    • Relevance threshold is set
  11. Save Configuration. Click the blue "Save Configuration" button at the bottom of the panel. A progress indicator appears as the system applies settings. Wait for the confirmation message: "✓ Configuration saved successfully".
  12. Run System Test. After saving, click "Run System Test". The system performs the following checks:
    • Verifies semantic search engine is responding
    • Confirms ML model is loaded and ready
    • Tests filter suggestion service
    • Validates cache layer (if enabled)
    Wait 30-60 seconds for test results.
  13. Verify Test Results. Successful setup shows:
    • ✓ Semantic search engine initialized successfully
    • ✓ ML model loaded and ready for inference
    • ✓ Filter suggestion service operational
    • ✓ System ready for user searches
    If any tests fail, review error messages and troubleshoot (see Troubleshooting section below).

Post-Setup Verification

After completing setup, perform these verification steps to ensure everything is working correctly:

Test Basic Search

As a test user (or yourself), try these searches in the search bar:

  1. Natural language search: Type "documents about security from last month" and press Enter.
  2. Verify results appear within 1-2 seconds.
  3. Verify filter suggestions appear below the search box (document type, date range, etc.).
  4. Click one suggested filter and verify results update immediately.

Test Filter Functionality

  1. Run a search for "API documentation".
  2. Click filter suggestion "api_reference" (document type).
  3. Verify results narrow to API reference documents only.
  4. Add date filter for the last 90 days.
  5. Verify results update to show only recent API documentation.

Verify Performance

Check search performance metrics:

  • Search response time should be under 2 seconds for typical queries
  • With caching enabled, subsequent identical searches should return in <500ms
  • No errors in system logs during search operations

Success Criteria

✓ Setup is successful when:
  • Natural language queries are understood and return relevant results
  • Filter suggestions appear within 500 milliseconds of each search
  • All suggested filters work correctly
  • Search results display relevance scores and organization
  • No errors appear in system logs or user-facing messages

Next Steps

After successful setup:

  1. Configure filter preferences specific to your organization's document types and categories
  2. If personalization was enabled, allow 2-4 weeks for the system to gather usage data and optimize results
  3. Set up monitoring and alerts for search performance metrics
  4. Conduct user acceptance testing with a small group of power users
  5. Prepare user training materials explaining new search capabilities
  6. Plan rollout to all users with communication about the new feature

Troubleshooting

Problem: System Test Fails with "ML Model Load Error"

Solution: Verify sufficient disk space (2+ GB) is available. Check that network connectivity to model repositories is working. Retry the test after waiting 5 minutes for the system to complete initialization.

Problem: Search Results Are Irrelevant or Missing

Solution: Check that minimum relevance score is not set too high. Try lowering from 0.7 to 0.5. Verify the ML model matches your language needs (e.g., use multilingual-e5 if indexing multiple languages). Reindex your document collection to ensure all content is searchable.

Problem: Filter Suggestions Not Appearing

Solution: Verify "Enable Smart Filter Suggestions" is checked in configuration. Check browser console for JavaScript errors. Try clearing browser cache and reloading the search page.

Problem: Slow Search Performance (>3 seconds)

Solution: Increase timeout setting from 5000 to 10000 milliseconds. Enable result caching. Consider upgrading server hardware or scaling search infrastructure. For very large datasets, consider splitting into multiple search indices.
