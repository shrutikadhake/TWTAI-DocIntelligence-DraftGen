Advanced Search API Reference

Version: 2.0 | Last Updated: 2024-12-19

Overview

The Advanced Search API provides endpoints for executing search queries with natural language understanding and configurable filtering. Developers can integrate semantic search capabilities into their applications with support for intelligent filter suggestions, faceted result organization, and personalized ranking.

API Endpoint: POST /api/v2/search

Execute a search query with optional filters and retrieve results ranked by relevance.

Request Parameters

Parameter Name Type Required Default Description
query string Yes — Search query in natural language. Maximum 500 characters. Example: "security from last month"
filters object No null Optional filters. Supports: document_type, date_range, author, tags
limit integer No 20 Results per page. Range: 1-100
offset integer No 0 Pagination offset for result sets
sort string No relevance Sort: relevance | date_desc | date_asc | popularity
include_suggestions boolean No true Include AI-generated filter suggestions

Common Error Responses ✨ NEW

The API returns standardized error responses with HTTP status codes. Handle errors gracefully using the status code and error message.

Error Response Format

All error responses follow this JSON structure:

{
  "error": "Error message describing what went wrong",
  "code": "ERROR_CODE",
  "details": {
    "field": "field_name",
    "issue": "specific validation or processing issue"
  }
}

HTTP Error Codes Reference

Code Status Description Example Error Response
400 Bad Request Invalid query syntax, missing required parameters, or malformed request body {"error": "Missing required parameter: query", "code": "MISSING_PARAMETER"}
401 Unauthorized Missing or invalid API authentication credentials. API key may be expired or invalid. {"error": "Invalid API token", "code": "INVALID_AUTH"}
403 Forbidden User does not have permission to access this resource or perform this action {"error": "Insufficient permissions for search", "code": "FORBIDDEN"}
404 Not Found The requested document, collection, or resource was not found {"error": "Document with ID not found", "code": "NOT_FOUND"}
429 Too Many Requests Rate limit exceeded. Too many API requests in too short a time period {"error": "Rate limit exceeded", "code": "RATE_LIMITED", "retry_after": 60}
500 Internal Server Error Search service encountered an unexpected error processing the request {"error": "Internal server error", "code": "INTERNAL_ERROR"}
503 Service Unavailable Search service is temporarily unavailable, under maintenance, or overloaded {"error": "Service temporarily unavailable", "code": "SERVICE_UNAVAILABLE"}

Common Error Scenarios and Solutions

Handling 429 (Rate Limited): Implement exponential backoff. Check the retry_after field in the response to know how long to wait before retrying.

Handling 503 (Service Unavailable): Implement retry logic with increasing delays. Service should recover within minutes.

Handling 400 (Bad Request): Check request syntax, ensure all required parameters are provided, and validate parameter values against API specification.

Configuration Options

Server-side configuration parameters that control search behavior:

Search Engine Configuration

Parameter Type Default Description
search_engine string elasticsearch Backend search engine: elasticsearch | opensearch | meilisearch
semantic_model string multilingual-e5-large ML model: multilingual-e5-large | all-mpnet-base-v2 | bge-large-en-v1.5
timeout_ms integer 5000 Query timeout in milliseconds. Range: 1000-30000
