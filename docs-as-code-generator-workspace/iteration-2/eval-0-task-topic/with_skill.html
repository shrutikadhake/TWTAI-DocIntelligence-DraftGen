Configure custom API rate limits

Learn how to set up custom rate limits for your API using the configuration file and CLI commands. This procedure enables you to define request thresholds that restrict API access when usage exceeds your specified limits.

Prerequisites

  • Access to the host server with root privileges
  • The global configuration file located at /etc/scanner/config.yml must be accessible
  • The scanner daemon service must be running on your system
  • A valid admin token for authenticating CLI commands

Steps

  1. Log into the host server as root.
  2. Open the file /etc/scanner/config.yml in a text editor.
  3. Locate the api_settings block in the configuration file.
  4. Set custom_limits_enabled to true in the api_settings section and save the file. Your configuration should resemble the following: 
    api_settings:
  timeout: 30
  custom_limits_enabled: true
  default_limit: 500
  5. Restart the scanner daemon service by running sudo systemctl restart scanner-daemon.
  6. Apply the custom limits using the CLI command: scanner-cli config update --api-limit <number> --window <seconds>, where <number> is your rate limit threshold and <seconds> is the time window in seconds. For example, to set a limit of 1,000 requests per 60 seconds, run scanner-cli config update --api-limit 1000 --window 60.

Expected results

When you apply the rate limit configuration successfully, the API returns a 200 OK: Rate limits updated response. When the rate limit is exceeded, the API returns a 429 Too Many Requests response, which indicates that your rate limit threshold is functioning as intended.

Troubleshooting

Issue: You receive a 403 Forbidden error with the message "Rate limit configuration is disabled globally."

This error occurs when you attempt to apply rate limits without first enabling custom limits in the configuration file. To resolve this issue, verify that you have completed the prerequisite step of setting custom_limits_enabled: true in /etc/scanner/config.yml and restarted the daemon service. The daemon does not hot-reload configuration changes, so you must restart the service after modifying the YAML file for changes to take effect.
