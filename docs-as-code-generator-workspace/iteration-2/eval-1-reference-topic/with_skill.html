Rate limit configuration reference

Configure custom API rate limits for your scanner daemon using the CLI command or YAML configuration file. Custom rate limits must be enabled in your configuration file before you can apply them.

Prerequisites

Before you apply custom rate limits, you must enable the feature in your configuration file:

  1. Log in to the host server as root.
  2. Open /etc/scanner/config.yml in a text editor.
  3. Under the api_settings section, set custom_limits_enabled: true.
  4. Save the file.
  5. Restart the scanner daemon: sudo systemctl restart scanner-daemon.

YAML configuration block structure

Add or update the api_settings block in your /etc/scanner/config.yml file with the following structure:

api_settings:
  timeout: 30
  custom_limits_enabled: true
  default_limit: 500

Configuration parameters

Parameter Type Description Default
timeout Integer (seconds) The API request timeout in seconds. 30
custom_limits_enabled Boolean Enable or disable custom rate limit configuration. Set to true to allow CLI commands to apply custom limits. false
default_limit Integer The default request limit if no custom limits are applied. 500

CLI command reference

After you enable custom limits in the YAML configuration, use the following CLI command to apply rate limit settings:

scanner-cli config update

Update the rate limit configuration for the API.

Syntax

scanner-cli config update --api-limit <number> --window <seconds>

Parameters

Parameter Type Required Description Valid values
--api-limit Integer Yes The maximum number of API requests allowed within the time window. Positive integers (e.g., 1000)
--window Integer Yes The time window in seconds during which the API limit applies. Positive integers (e.g., 60)

Example

Set the API rate limit to 1000 requests per 60 seconds:

scanner-cli config update --api-limit 1000 --window 60

Response codes

Code Description Cause
200 OK Rate limits updated successfully. Configuration applied successfully.
403 Forbidden Rate limit configuration is disabled globally. Verify that custom_limits_enabled: true is set in api_settings and the daemon has been restarted.
429 Too Many Requests API request limit has been exceeded. The client must wait until the time window resets before sending additional requests.

Verify rate limits are applied

After you apply custom rate limits, you can verify they are working by sending requests to your API endpoint until you reach the limit. When you exceed the rate limit, the server returns a 429 Too Many Requests response.

For example, if you set --api-limit 1000 --window 60, the 1001st request within 60 seconds triggers a rate limit error.
