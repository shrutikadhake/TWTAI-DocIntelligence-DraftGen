API Rate Limit Configuration Reference

Configure custom API rate limits for the Scanner service using the command-line interface and YAML configuration.

Overview

The Scanner service allows administrators to configure custom rate limits for API requests. Rate limits are defined by two parameters: the maximum number of allowed requests and the time window in which those requests are counted.

Custom rate limits require explicit enablement in the global configuration file and a service restart before they take effect.

Prerequisites

  • Root or administrative access to the host server
  • Access to the Scanner service configuration file at /etc/scanner/config.yml
  • Permission to restart the scanner-daemon service

Configuration Parameters

--api-limit

Description
Specifies the maximum number of requests allowed within the time window.
Type
Integer
Valid Values
Positive integers (e.g., 500, 1000, 5000)
Default Value
Not specified
Example
--api-limit 1000

--window

Description
Specifies the time window (in seconds) for counting requests.
Type
Integer (seconds)
Valid Values
Positive integers representing seconds (e.g., 30, 60, 300)
Default Value
Not specified
Example
--window 60

CLI Command Signature

scanner-cli config update

Updates the API rate limit configuration.

Syntax

scanner-cli config update --api-limit <number> --window <seconds>

Parameters

Parameter Type Required Description
--api-limit Integer Yes Maximum number of requests allowed in the time window
--window Integer Yes Time window in seconds for counting requests

Example

scanner-cli config update --api-limit 1000 --window 60

Success Response

200 OK: Rate limits updated.

Error Responses

Status Code Message Cause
403 Rate limit configuration is disabled globally. custom_limits_enabled is not set to true in the configuration file

YAML Configuration Block Structure

Rate limit settings are defined within the api_settings block in /etc/scanner/config.yml.

Configuration File Location

/etc/scanner/config.yml

Configuration Block

api_settings:
  timeout: 30
  custom_limits_enabled: true
  default_limit: 500

Block Properties

Property Type Description Required
timeout Integer (seconds) API request timeout duration Not specified
custom_limits_enabled Boolean Enables or disables custom rate limit configuration. Must be set to true for the CLI command to function. Yes
default_limit Integer Default rate limit when custom limits are not explicitly set Not specified

Service Restart Requirement

Changes to the YAML configuration file do not take effect immediately. The Scanner daemon does not support hot-reload of configuration files.

Restart Command

sudo systemctl restart scanner-daemon

The service must be restarted after modifying the /etc/scanner/config.yml file for configuration changes to take effect.

Configuration Procedure

  1. Log into the host server as root.
  2. Open /etc/scanner/config.yml in a text editor.
  3. Under api_settings, set custom_limits_enabled: true and save the file.
  4. Restart the service using sudo systemctl restart scanner-daemon.
  5. Apply the custom limits using the CLI: scanner-cli config update --api-limit <number> --window <seconds>.

Limitations and Notes

  • The custom_limits_enabled property must be explicitly set to true before any CLI-based rate limit updates will be accepted.
  • Configuration changes made to the YAML file do not take effect until the daemon is restarted.
  • Rate limit enforcement begins after the 1001st request is made within the defined window (i.e., requests 1–1000 are accepted; the 1001st request receives a 429 Too Many Requests response).

Missing or Incomplete Information

Parameter Definitions and Type Information

  • Default values: The default values for --api-limit and --window parameters are not documented in the source material.
  • Range constraints: No maximum or minimum value constraints are specified for --api-limit or --window.
  • Configuration file properties: The purpose and default values of timeout and default_limit properties in the api_settings block are not fully documented.
  • Authentication requirements: Whether an admin token or specific authentication is required for the scanner-cli config update command is implied but not explicitly documented.
  • Rate limit behavior: The exact behavior when the rate limit is exceeded (besides the 429 response) is not documented (e.g., request queuing, exponential backoff, client-side retry guidance).
  • Multiple rate limit configurations: It is unclear whether multiple rate limit configurations can coexist or be applied to different endpoints.
