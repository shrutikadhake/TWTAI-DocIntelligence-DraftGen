Rate Limit Configuration Reference

This reference documents the configuration parameters for custom API rate limits in the scanner daemon, including the YAML configuration structure and CLI command syntax.

Configuration Structure

Rate limit configuration is managed in the global configuration file at /etc/scanner/config.yml. Before applying rate limits via the CLI, you must enable custom limits in the YAML configuration.

YAML Configuration Block

The rate limit settings are located under the api_settings block:

api_settings:
  timeout: 30
  custom_limits_enabled: true
  default_limit: 500

The custom_limits_enabled parameter must be set to true before CLI commands will be accepted.

Parameters

Parameter Name Type Valid Values Description
api-limit Integer Positive integer (example: 1000) Specifies the maximum number of API requests allowed within the specified time window. When this threshold is exceeded, the API returns a 429 Too Many Requests response.
window Integer Positive integer representing seconds (example: 60) Specifies the time window in seconds during which the request limit applies. The limit resets after this interval.
custom_limits_enabled Boolean true or false Enables or disables custom rate limit configuration. Must be set to true in the YAML file before CLI commands are accepted. Default: false.
timeout Integer Positive integer in seconds (example: 30) Specifies the API timeout value in seconds.
default_limit Integer Positive integer (example: 500) Sets the default API request limit if no custom limit is configured.

CLI Command Syntax

Apply custom rate limits using the scanner CLI tool:

scanner-cli config update --api-limit <number> --window <seconds>

Parameters

  • --api-limit <number>: The maximum number of requests allowed in the specified window (integer value).
  • --window <seconds>: The time window in seconds during which the limit applies (integer value).

Example

scanner-cli config update --api-limit 1000 --window 60

This command sets the rate limit to 1000 requests per 60-second window.

Service Restart Requirement

The scanner daemon does not reload configuration changes dynamically. After modifying the YAML configuration file, you must restart the daemon for changes to take effect:

sudo systemctl restart scanner-daemon

Response Codes

Response Code Meaning
200 OK Rate limits were updated successfully with message: "Rate limits updated."
403 Forbidden Rate limit configuration is disabled globally. Enable custom_limits_enabled in the YAML configuration file and restart the daemon.
429 Too Many Requests The configured rate limit has been exceeded. The client must wait until the time window resets before making additional requests.
