Configure Custom API Rate Limits

Before You Begin

Before you configure custom API rate limits, you need:

  • Root access to the host server
  • A text editor to modify the configuration file
  • A valid admin token for authentication
  • Access to the Scanner daemon configuration file at /etc/scanner/config.yml

Important: Custom rate limit configuration is disabled by default. You must enable it in the global configuration file before proceeding.

Configure Rate Limits

Follow these steps to configure custom API rate limits for your Scanner service:

  1. Log into the host server as root.

  2. Open the configuration file /etc/scanner/config.yml in a text editor.

  3. Locate the api_settings block. If you don't see one, add it.

    Update the configuration to set custom_limits_enabled to true:

    api_settings:
  timeout: 30
  custom_limits_enabled: true
  default_limit: 500

  4. Save the configuration file.

  5. Restart the Scanner daemon to apply the changes:

    sudo systemctl restart scanner-daemon

  6. Apply your custom rate limits using the Scanner CLI. Replace <number> with your desired rate limit and <seconds> with the time window in seconds:

    scanner-cli config update --api-limit <number> --window <seconds>

    For example, to set a limit of 1000 requests per 60 seconds:

    scanner-cli config update --api-limit 1000 --window 60

Verify Configuration

After applying the rate limits, verify that they are working correctly. Send requests to your API endpoint to test the limit. When you exceed the configured limit, the service should return a 429 Too Many Requests response.

For example, if you set a limit of 1000 requests per 60 seconds, the 1001st request should receive a 429 response.

Troubleshooting

Error 403: Forbidden

If you receive a 403 Forbidden error with the message "Rate limit configuration is disabled globally," you have missed a prerequisite step.

Solution: Return to step 3 above and ensure that you have set custom_limits_enabled: true in the api_settings block of /etc/scanner/config.yml. After saving the file, restart the daemon in step 5 and retry the CLI command.

Rate Limits Not Applied

If rate limits do not apply immediately after running the CLI command:

  • Confirm that you restarted the scanner-daemon after modifying the YAML file. The daemon does not reload configuration changes automatically.
  • Verify your admin token has not expired.
  • Check that the Scanner daemon is running: sudo systemctl status scanner-daemon
