Custom API Rate Limits

Overview

Custom API rate limits enable AppScan Enterprise administrators to control the frequency of API requests within your system. By configuring these limits, you can prevent resource exhaustion, protect against unintended overuse, and ensure fair distribution of API access across multiple clients.

Purpose

The custom API rate limits feature provides granular control over API request throttling. When enabled and configured, the system rejects requests that exceed the specified limit within a defined time window, returning a 429 Too Many Requests response to the requesting client.

This mechanism protects your AppScan infrastructure by:

  • Preventing single clients from monopolizing API resources
  • Maintaining system stability under high-traffic conditions
  • Allowing administrators to define thresholds appropriate to their deployment size

Key Concepts

API Limit

The maximum number of requests permitted within a specified time window. For example, an API limit of 1000 requests with a 60-second window allows up to 1000 requests per minute.

Time Window

The duration (in seconds) over which the API limit is measured and reset. After each window elapses, the request counter resets to zero.

Scanner Daemon

The background service (scanner-daemon) that enforces API rate limits. The daemon must be restarted after configuration changes to load new rate limit values.

System Components and Interaction

Global Configuration File

The YAML configuration file located at /etc/scanner/config.yml contains the global feature switch for custom API rate limits.

api_settings block
The section within config.yml that governs API behavior.
custom_limits_enabled parameter
A boolean flag (true or false) that enables or disables the custom API rate limits feature globally. This parameter must be set to true before the rate limit CLI commands will be accepted.
Note: Configuration changes in config.yml are not automatically reloaded. You must restart the scanner daemon for changes to take effect.

Command-Line Interface (CLI)

The scanner-cli command-line tool provides the interface for applying custom rate limits to the running system. The tool communicates with the scanner daemon to enforce the specified limits.

scanner-cli config update
The CLI command used to apply custom rate limit values.
--api-limit parameter
Specifies the maximum number of requests allowed within the time window.
--window parameter
Specifies the duration of the time window in seconds over which the limit applies.

Configuration Prerequisite and Workflow

The custom API rate limits feature requires a specific sequence of steps to function correctly. Each step must be completed in order.

  1. Enable the feature in the global configuration:

    Open the file /etc/scanner/config.yml and locate the api_settings block. Set custom_limits_enabled to true and save the file.

    Without this prerequisite, the CLI will reject rate limit commands with a 403 Forbidden error: "Rate limit configuration is disabled globally."

  2. Restart the scanner daemon:

    Run the following command to restart the service and load the updated configuration:

    sudo systemctl restart scanner-daemon

    The daemon does not hot-reload configuration changes and must be restarted explicitly.

  3. Apply custom rate limit values:

    After the daemon restarts, use the CLI command to set your desired rate limits:

    scanner-cli config update --api-limit <number> --window <seconds>

    Replace <number> with the maximum request count and <seconds> with the time window duration.

    On success, the system returns 200 OK: Rate limits updated.

Error Responses and Troubleshooting

403 Forbidden Error

Error message: "Rate limit configuration is disabled globally."

Cause: The custom_limits_enabled parameter in /etc/scanner/config.yml is set to false or the scanner daemon has not been restarted since the configuration change.

Resolution: Ensure that custom_limits_enabled: true is set in the api_settings block and that the scanner daemon has been restarted.

429 Too Many Requests

Error message: HTTP 429 response returned to the requesting client.

Cause: The API request count has exceeded the configured limit within the specified time window.

Resolution: Wait for the time window to reset before retrying requests, or increase the configured API limit if legitimate demand exceeds the current threshold.

Technical Terms Clarification

Scanner Daemon
A background service process that continuously runs on the AppScan Enterprise host and enforces configured rate limit policies. It requires explicit restart to load configuration changes.
Authentication Token
A credential used to verify administrator identity when executing CLI commands. The token must be valid and not expired to execute rate limit configuration changes.
Hot-reload
The ability to apply configuration changes without restarting a service. The scanner daemon does not support hot-reload for custom API rate limit settings.
Time Window Reset
The automatic clearing of the request counter at the end of each defined time window, allowing new requests to be counted against the limit for the next window.

Summary

Custom API rate limits are a three-step feature: first enable the feature globally, then restart the daemon to apply that setting, and finally use the CLI to set your specific rate limit thresholds. The prerequisite step (enabling in the YAML configuration) is critical and must be completed before CLI commands will be accepted. This design ensures that rate limiting can be disabled at the system level while still allowing per-instance configuration through the CLI once enabled.
