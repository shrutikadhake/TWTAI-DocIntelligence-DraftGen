Configure custom API rate limits

Configure custom rate limits for your API to control request volume and prevent abuse. This task requires modifying the global configuration file and using the CLI to apply the limits.

Prerequisites

  • Root or admin access to the host server
  • A valid admin authentication token
  • Write permissions for /etc/scanner/config.yml
  • The scanner daemon installed and available for restart

Steps

  1. Log into the host server as root.
  2. Open /etc/scanner/config.yml in a text editor.
  3. Locate the api_settings block. Under this section, set custom_limits_enabled: true and save the file.
  4. Restart the daemon by running sudo systemctl restart scanner-daemon. The daemon does not hot-reload configuration changes.
  5. Apply the custom rate limits using the CLI: scanner-cli config update --api-limit <number> --window <seconds>
    • Replace <number> with the maximum number of requests allowed.
    • Replace <seconds> with the time window in seconds (for example, 60 for one minute).
  6. Validate the configuration by sending test requests to the API endpoint. Once the limit is exceeded, the API should return a 429 Too Many Requests response.

Expected results

After you apply the custom rate limits, requests to the API are accepted until the limit is reached within the specified time window. When the limit is exceeded, the API returns a 429 Too Many Requests response and rejects further requests until the window expires.

Troubleshooting

Error: 403 Forbidden - Rate limit configuration is disabled globally

This error occurs when custom_limits_enabled is not set to true in the api_settings block. Verify that you completed step 3 and that the YAML file was saved correctly. Check that the setting appears as follows:

api_settings:
  custom_limits_enabled: true

Still receiving 403 error after enabling the setting

The daemon caches the configuration in memory and does not automatically reload configuration file changes. After you modify the YAML file, you must restart the daemon as described in step 4: sudo systemctl restart scanner-daemon

Error with authentication token

Verify that your admin token is still valid. Tokens may expire over time. Generate a new admin token and retry the CLI command.
