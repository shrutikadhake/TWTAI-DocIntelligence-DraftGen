Scanner rate limit configuration reference

Overview

The Scanner API enables you to configure custom rate limits to control how many requests the system accepts within a specified time window. You enable custom rate limits in the global configuration file, then use the CLI to apply limits per deployment.

Prerequisites

You need administrator access to the Scanner host server and a valid admin authentication token to modify rate limit settings.

Authentication

The CLI uses admin authentication tokens for all configuration requests. Your token must be passed as an environment variable or stored in the local configuration:

export SCANNER_ADMIN_TOKEN=<your-admin-token>

Contact your system administrator to generate a new admin token if you do not have one or if your token has expired.

Enable custom rate limits

Before you apply any custom limits, enable the feature in the global configuration file.

Step 1: Open the configuration file

Log in to your host server as root and open the configuration file in a text editor:

/etc/scanner/config.yml

Step 2: Set the custom limits flag

Locate the api_settings block in the configuration file. Set custom_limits_enabled to true:

api_settings:
  timeout: 30
  custom_limits_enabled: true
  default_limit: 500

Save the file.

Step 3: Restart the Scanner daemon

The Scanner daemon does not hot-reload configuration changes. Restart the daemon to apply the configuration:

sudo systemctl restart scanner-daemon

Configure rate limits with the CLI

After you enable custom limits in the configuration file, use the CLI to set the rate limit parameters.

Command syntax

Use the scanner-cli config update command to apply rate limits:

scanner-cli config update --api-limit <requests> --window <seconds>

Parameters

Parameter Type Description Example
--api-limit integer The maximum number of requests allowed within the specified window. 1000
--window integer The time window in seconds over which the limit is measured. 60

Example

This example sets a limit of 1000 requests per 60 seconds:

scanner-cli config update --api-limit 1000 --window 60

This configuration allows approximately 16.7 requests per second. On success, the CLI returns the following response:

200 OK: Rate limits updated.

YAML configuration reference

The global configuration file defines the API settings that control rate limiting behavior.

api_settings block

The api_settings block in /etc/scanner/config.yml contains the following properties:

Property Type Required? Description Default
timeout integer No Request timeout in seconds. 30
custom_limits_enabled boolean Yes Enables custom rate limit configuration via CLI. Set to true to allow rate limit updates. false
default_limit integer No The default request limit used when custom limits are not configured. 500

Complete example

api_settings:
  timeout: 30
  custom_limits_enabled: true
  default_limit: 500

Responses and error handling

The system responds to CLI commands and requests with the following status codes and messages:

Success responses

Status code Message Meaning
200 OK: Rate limits updated. Rate limits have been successfully applied.

Error responses

Status code Message Cause Solution
400 Bad Request: Invalid parameter format. The --api-limit or --window parameter contains invalid values (non-numeric or out of range). Ensure both parameters are positive integers. For example, use --api-limit 1000 --window 60.
401 Unauthorized: Authentication failed. The admin token is missing, invalid, or expired. Generate a new admin token and set the SCANNER_ADMIN_TOKEN environment variable before running the CLI command.
403 Forbidden: Rate limit configuration is disabled globally. The custom_limits_enabled flag is set to false in the configuration file. Enable custom limits by setting custom_limits_enabled: true in /etc/scanner/config.yml, then restart the daemon.
429 Too Many Requests A client has exceeded the configured rate limit. The client must reduce the request rate and retry after the specified window expires.
500 Internal Server Error An unexpected error occurred while processing the request. Verify that the Scanner daemon is running and the configuration file is valid. Restart the daemon if necessary.

Test the configuration

After you apply the rate limits, verify that the limits are working correctly by sending requests at the configured rate.

Example: Verify the rate limit

This example uses curl to test a rate limit of 1000 requests per 60 seconds:

for i in {1..1001}; do curl https://api.example.com/endpoint; done

When you exceed the rate limit, the API returns HTTP 429 (Too Many Requests). The request succeeds for all requests up to the limit, then returns 429 for subsequent requests within the same window.

Troubleshooting

Configuration changes are not taking effect

The Scanner daemon does not automatically reload configuration file changes. After you modify the YAML file, restart the daemon:

sudo systemctl restart scanner-daemon

Authentication fails when applying rate limits

Verify that your authentication token is valid and has not expired. Generate a new admin token if needed.

Still receiving 403 Forbidden errors

Ensure that you have completed the following steps in order:

  1. Set custom_limits_enabled: true in the api_settings block.
  2. Save the configuration file.
  3. Restart the Scanner daemon.
  4. Run the CLI command with a valid authentication token.
