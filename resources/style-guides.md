## Documentation Style Guide

Apply the documentation style guide specified by the user.

Supported style guides include:

- Microsoft Writing Style Guide (Default)
- IBM Style
- Google Developer Documentation Style Guide
- Custom Style Guide provided by the user

If no style guide is specified, follow the Microsoft Writing Style Guide.

### Microsoft Writing Style Guide

When Microsoft style is selected:

#### Language

- Use clear, concise, conversational language.
- Prefer active voice.
- Write in present tense.
- Address the user directly where appropriate.
- Avoid unnecessary words and redundancy.

#### Procedures

- Write procedures as numbered steps.
- Begin each step with an action verb.
- Keep each step focused on a single action.

#### Headings

- Use descriptive headings.
- Maintain a logical heading hierarchy.
- Keep headings concise.

#### Lists

- Use unordered lists for prerequisites, notes, warnings, permissions, and related information.
- Use ordered lists for sequential procedures.

#### Technical Terms

- Preserve product names and technical terminology.
- Use consistent terminology throughout the document.
- Format commands, filenames, configuration values, and API names using `<code>`.

---

### IBM Style

When IBM style is selected:

#### Language

- Use precise, task-oriented language.
- Use active voice.
- Eliminate unnecessary words.
- Keep sentences concise and unambiguous.

#### Procedures

- Organize procedures into clearly numbered steps.
- Ensure each step performs one primary action.
- Present information in a logical sequence.

#### Documentation Structure

- Organize related information into clearly defined sections.
- Separate conceptual, procedural, and reference information where applicable.

#### Terminology

- Maintain consistent terminology.
- Preserve technical accuracy.
- Avoid colloquial language.

---

### Google Developer Documentation Style Guide

When Google style is selected:

#### Language

- Use plain language.
- Write for a global audience.
- Prefer short sentences.
- Use active voice.
- Avoid unnecessary complexity.

#### Procedures

- Write concise, task-focused instructions.
- Use numbered procedures.
- Present one action per step.

#### Readability

- Keep paragraphs short.
- Use informative headings.
- Break long content into smaller sections.

#### Technical Content

- Preserve technical terminology.
- Clearly distinguish commands, code, and configuration values.

---

### General Documentation Rules

Regardless of the selected style guide:

- Preserve the meaning of the source JSON.
- Do not invent or infer information.
- Do not omit important technical details.
- Generate semantic HTML5.
- Produce properly indented HTML.
- Ensure all HTML tags are correctly nested and closed.
- Omit documentation sections that are not present in the input.
